# Contributing

Everyone can propose changes and report games. You do not need to submit a pull request to participate.

## Open an issue first

Search existing issues, then use the balance proposal, clarification or playtest template. Keep one problem per proposal. Identify the exact official source and version; link to official material instead of copying large passages.

Proposals should address Matched Play, the repository's focus. Describe the applicable Matched Play restrictions, the problem, available evidence and the outcome you want. A proposed solution is welcome but not required. Small samples and personal experience are useful when labelled honestly.

Maintainers record a triage outcome: needs evidence, accepted for testing, deferred, duplicate or out of scope. Rejection should include a reason.

## Prepare a pull request

Fork the repository and create a branch, or ask a maintainer to prepare the edit. Link the issue. Write exact points adjustments or replacement wording in BALANCE_PATCH.md and add a concise CHANGELOG.md entry under Unreleased.

Include the rationale, alternatives considered, affected interactions and test plan in the pull request. Separate unrelated changes. Do not include an unapproved proposal in a stable release.

Until the first release, the baseline and scope must be explicitly agreed and recorded. Never invent official profile values or rules.

## Playtest

Record the pull request and commit SHA tested, full lists and points, battle groups, player experience, scenario, terrain, allies, blessings and any other restrictions. Include the result, victory points, relevant interactions and adverse effects.

Use pseudonyms rather than contact information. Keep games using different revisions separate. Test both intended use and potentially abusive combinations, including ally use where permitted.

Set acceptance and rollback criteria before testing. Aim for four to six weeks of testing across independent groups for substantive changes. Lack of evidence is a reason to defer, not to claim that a change is balanced.

## Review and release

The council reviews wording and evidence under GOVERNANCE.md. Authors need independent review. A merged change is work for a future patch until included in a tagged release.

## Contribution terms

Submit only material you have the right to contribute. By submitting original text for inclusion, you agree to license that contribution under CC BY-SA 4.0 as scoped in NOTICE.md. Identify third-party material and its permissions separately.

Do not upload scans, artwork, whole official rulebooks or copied profile databases. This project publishes community changes alongside references to the official baseline.
